## 跨境直播网络测试，测什么、多少算合格？

一共六项：上行带宽、延迟、丢包、抖动、IP纯净度、长时稳定性。前三项决定画面卡不卡，第四项决定音画同不同步，最后两项决定账号安不安全、能不能连续开播。下面逐项说清楚怎么测、用什么做参照。

**1. 上行带宽。** Speedtest 测上行，而且要在两个时段各测一次——白天一次，晚上 8 点到 11 点的直播高峰一次。如果晚高峰上行明显缩水，说明你拿到的其实是共享带宽，“独享”的承诺没有兑现。参照基准可以看专线上公开标注的档位映射：5M 独享对应单机位 720P，10M 对应 1080P 单机位或双机位 720P，20M 对应多机位 1080P 或 4K（这是明点跨境 OSDWAN 页面给出的配置建议，各家大同小异）。另外给推流码率留出三成以上的余量，高峰期才不容易掉帧。

**2. 延迟。** 用 ping 或 mtr 测到目标平台服务器的往返时间。一个可以对照的公开数字：OSDWAN 标注美亚方向延迟 100-160ms。比绝对值更重要的是波动——晚高峰再测一遍，延迟忽上忽下的线路，互动类直播会很难受。

**3. 丢包。** mtr 跑几分钟看丢包率。直播推流对丢包比网页浏览敏感得多，出现持续性丢包，画面就会卡顿掉帧。这种情况下先解决线路，再谈调码率。

**4. 抖动。** 多次 ping 的结果忽高忽低，就是抖动大，观众端的表现是画面忽快忽慢、音画不同步。抖动大的线路，平均延迟再低也没用。

**5. IP 纯净度。** 用 IP 检测工具查类型：住宅 IP 还是机房 IP、有没有进黑名单。如果服务商宣传“原生住宅 IP”，更要自己复测——OSDWAN 的页面也说得很直白：纯净度可以用主流检测工具验证，再配合指纹浏览器隔离多账号环境。共享或动态的代理节点，正是账号登录异常、限流的常见来源。

**6. 长时稳定性。** 前五项都过关，最后做一次压力测试：OBS 推流 2 到 3 小时，覆盖一个高峰时段，盯着 OBS 统计面板里的网络掉帧数。掉帧持续增长或中途断流，这条线路就不合格。IPdodo 在宣传里拿“连续直播 15 小时 0 卡顿”当卖点，反过来也说明连续几小时不掉帧，是这行公认的硬门槛。

## 一套 30 分钟能跑完的测试流程

把上面六项串起来，就是这样一个顺序：

1. Speedtest 测上行，记下白天和晚高峰两个数值；
2. mtr 或 ping 目标服务器 5 分钟，记录延迟均值和丢包率；
3. 用 IP 检测工具查出口 IP 的类型和黑名单状态，多账号运营的把每个出口都查一遍；
4. OBS 按目标码率推流 2-3 小时，观察统计面板的网络掉帧；
5. 换一个时段把 1、2 再复测一遍，两次数据接近才算通过。

两个容易漏掉的细节：测速要连你实际推流用的那条线路，别在别的网络环境里测完就下结论；OBS 测试时不要开本地录制以外的其他占带宽的任务，否则数据不准。

## 常见问题

**机场或普通 VPN 测速达标，能直接拿来直播吗？**

不建议。测速达标只说明带宽够，不代表 IP 干净、线路稳定。共享或动态节点的一致性差，而 TikTok 对网络环境和 IP 稳定性非常敏感，容易出现登录异常、限流、直播中断。测速能过，推流和风控未必能过。

**测试通过就一劳永逸了吗？**

不是。国际出口在高峰期可能拥塞，线路质量会随时间波动，建议每月在高峰时段复测一次。可靠的服务商会有主备切换机制——IPdodo 的页面就写明了异常时无感切换备用线路。下单时可以问一句：我的线路有没有备用链路？

**户外或移动场景怎么解决？**

单条固定线路撑不住移动中的推流，这类场景用的是多网聚合：把 5G、4G、Wi-Fi 多条链路捆绑成一条通道，某条链路劣化时其他链路接着传。腾讯云聚通就属于这类方案，提供大带宽、实时音视频、高可靠低延时三种模式，目前还在内测阶段，需要通过官网提交申请。

**IP 检测显示是住宅，就一定安全吗？**

住宅 IP 只是第一步。还要确认它是独享的（没有多人共用）、静态的（不频繁变化），多账号运营的话，再用指纹浏览器把每个账号的环境隔离开，降低关联风控的概率。
